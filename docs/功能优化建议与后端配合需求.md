## 2. 核心缺失功能（高优先级）

### 2.1 钱包充值系统

**现状**：用户有 `Balance` 字段，但只能通过下单消费，**没有任何充值入口**。

**用户体验影响**：

- 新用户余额为 0，无法购买任何商品
- 余额用完后无法补充，导致用户流失

**后端配合需求**：

| 接口                     | 方法     | 说明                   |
| ---------------------- | ------ | -------------------- |
| `POST /user/recharge`  | 充值     | 接收充值金额，增加用户余额，创建充值记录 |
| `GET /user/balanceLog` | 余额流水   | 分页返回余额变动记录（充值/消费/退款） |
| `POST /pay/recharge`   | 微信充值   | 微信支付充值回调             |
| 新建 `RechargeModel`     | 充值记录模型 | 记录充值金额、时间、方式、状态      |

**前端改动**：

- 用户主页增加「充值」按钮
- 支付页增加「去充值」入口
- 余额明细页面

***

### 2.2 商品收藏/愿望单

**现状**：无任何收藏功能，用户想买但暂时不付款的商品无法标记。

**用户体验影响**：

- 看到喜欢的商品只能立即购买或放弃
- 无法跟踪感兴趣的商品价格变化

**后端配合需求**：

| 接口                            | 方法     | 说明                           |
| ----------------------------- | ------ | ---------------------------- |
| `POST /product/favorite`      | 添加收藏   | 用户ID + 商品ID                  |
| `DELETE /product/favorite`    | 取消收藏   | 用户ID + 商品ID                  |
| `GET /product/favorite/list`  | 收藏列表   | 分页返回用户收藏的商品列表                |
| `GET /product/favorite/check` | 检查是否收藏 | 返回布尔值                        |
| 新建 `FavoriteModel`            | 收藏模型   | userId, productId, createdAt |

**前端改动**：

- 商品详情页增加「收藏」爱心按钮
- 用户主页增加「我的收藏」板块
- 商品卡片上增加收藏状态图标

***

### 2.3 卖家商品分类管理（店铺主页）

**现状**：卖家主页只是简单列出所有商品，没有分类、没有店铺装修。

**用户体验影响**：

- 买家进入卖家主页后难以快速找到想要的商品
- 卖家无法建立自己的品牌形象

**后端配合需求**：

| 接口                           | 方法     | 说明                                                      |
| ---------------------------- | ------ | ------------------------------------------------------- |
| `POST /user/shopInfo/update` | 更新店铺信息 | 店铺公告、店铺名称、店铺头像                                          |
| 可复用现有字段                      | —      | `UserModel` 可扩展 `shopName`, `shopDesc`, `shopBanner` 字段 |

**前端改动**：

- 卖家主页增加店铺头部 Banner、公告区域
- 商品按分类/价格筛选
- 店铺数据统计（总销量、好评率）

***

### 2.4 订单评价星级评分

**现状**：评价只有文字内容，缺少星级评分。

**用户体验影响**：

- 无法直观判断卖家/商品的好坏程度
- 其他买家难以快速筛选高质量卖家

**后端配合需求**：

| 接口                         | 方法             | 说明          |
| -------------------------- | -------------- | ----------- |
| 修改 `ReviewModel`           | 增加 `rating` 字段 | 1-5 星整数     |
| 修改 `POST /review/add`      | 接收 rating      | 增加校验 1-5    |
| `GET /review/sellerRating` | 卖家评分统计         | 返回平均分、各星级数量 |
| 修改 `ReviewQueueModel`      | 适配 rating      | —           |

**前端改动**：

- 评价弹窗增加星级选择（点击星星）
- 评价卡片显示星星
- 用户主页显示卖家综合评分

***

### 2.5 商品浏览历史

**现状**：商品详情记录了 `viewCount`（总浏览量），但不记录哪些用户看过。

**用户体验影响**：

- 用户想找回之前看过的商品非常困难
- 无法基于浏览历史做个性化推荐

**后端配合需求**：

| 接口                              | 方法     | 说明                          |
| ------------------------------- | ------ | --------------------------- |
| `POST /product/viewHistory`     | 记录浏览   | 用户ID + 商品ID（在 getPro 时自动记录） |
| `GET /product/viewHistory/list` | 浏览历史列表 | 分页返回，按浏览时间倒序                |
| 新建 `ViewHistoryModel`           | 浏览历史模型 | userId, productId, viewedAt |

**前端改动**：

- 用户主页增加「最近浏览」板块
- 可跳转到对应的商品详情

***

### 2.6 支付方式扩展（微信支付启用）

**现状**：微信支付路由 (`Pay.js`, `PayWebhook.js`) 已被注释，目前仅支持余额支付。

**用户体验影响**：

- 余额不足就无法购买
- 用户需要先充值才能购买，流程繁琐

**后端配合需求**：

| 接口                    | 方法     | 说明                                    |
| --------------------- | ------ | ------------------------------------- |
| `POST /pay/create`    | 创建支付订单 | 调用微信支付统一下单接口                          |
| `POST /pay/webhook`   | 微信支付回调 | 更新订单支付状态                              |
| 完善 `config/xorpay.js` | 支付配置   | 填写微信支付商户号、密钥等                         |
| 修改 `OrderModel`       | 支付方式字段 | 增加 `payMethod: ['balance', 'wechat']` |

**前端改动**：

- 支付页增加「微信支付」选项
- 支付方式切换 UI

## 3. 体验增强功能（中优先级）

### 3.1 站内即时通讯/留言系统

**现状**：买卖双方无法直接沟通，买家有疑问只能放弃购买。

**用户体验影响**：

- 无法咨询商品细节（成色、尺寸等）
- 无法协商价格或配送方式
- 交易纠纷无法留证

**后端配合需求**：

| 接口                          | 方法     | 说明                                                   |
| --------------------------- | ------ | ---------------------------------------------------- |
| `POST /message/send`        | 发送消息   | senderId, receiverId, content, productId(可选)         |
| `GET /message/conversation` | 获取会话列表 | 按最后消息时间排序                                            |
| `GET /message/list`         | 获取聊天记录 | 分页，按时间正序                                             |
| `PUT /message/read`         | 标记已读   | 标记某会话所有消息为已读                                         |
| `GET /message/unreadCount`  | 未读消息数  | —                                                    |
| 新建 `ConversationModel`      | 会话模型   | 参与双方ID、最后消息、最后时间、未读数                                 |
| 新建 `MessageModel`           | 消息模型   | conversationId, senderId, content, createdAt, isRead |
| 可选: WebSocket               | 实时推送   | Socket.io 实现即时消息                                     |

**前端改动**：

- 商品详情页增加「联系卖家」按钮
- 导航栏增加「消息」入口（带未读红点）
- 聊天窗口组件（类似微信对话框）

***

### 3.2 商品搜索增强

**现状**：仅支持关键词模糊搜索。

**用户体验影响**：

- 搜索结果不够精准
- 无法按价格、时间、销量排序
- 没有搜索建议/热词

**后端配合需求**：

| 接口                           | 方法     | 说明                                                       |
| ---------------------------- | ------ | -------------------------------------------------------- |
| 修改 `POST /product/searchPro` | 增加排序参数 | `sortBy: ['price_asc', 'price_desc', 'newest', 'sales']` |
| `GET /product/searchSuggest` | 搜索建议   | 输入前缀返回建议词列表                                              |
| `GET /product/hotSearch`     | 热搜词    | 返回近期热门搜索词 TOP10                                          |
| 新建 `SearchLogModel`          | 搜索日志   | userId, keyword, createdAt                               |

**前端改动**：

- 搜索框增加下拉建议
- 搜索结果页增加排序选项
- 搜索框占位显示热搜词

***

### 3.3 订单物流跟踪

**现状**：订单只有状态流转（待付款→待发货→待收货→已完成），没有物流信息。

**用户体验影响**：

- 买家不知道包裹到哪里了
- 卖家无法批量管理发货

**后端配合需求**：

| 接口                           | 方法     | 说明                                                |
| ---------------------------- | ------ | ------------------------------------------------- |
| `PUT /order/ship`            | 发货操作   | 增加 `trackingNumber`, `logisticsCompany` 字段        |
| `PUT /order/updateLogistics` | 更新物流信息 | —                                                 |
| `GET /order/logistics`       | 查询物流   | 返回物流跟踪信息                                          |
| 修改 `OrderModel`              | 增加物流字段 | `trackingNumber`, `logisticsCompany`, `shippedAt` |

**前端改动**：

- 订单详情增加「物流信息」板块
- 发货时卖家输入快递单号
- 物流进度时间线展示

***

### 3.4 个性化推荐

**现状**：首页只有「热门商品」和「每日好物」，没有基于用户行为的个性化推荐。

**用户体验影响**：

- 每个用户看到的内容完全一样
- 缺少发现感兴趣商品的渠道

**后端配合需求**：

| 接口                       | 方法    | 说明               |
| ------------------------ | ----- | ---------------- |
| `GET /product/recommend` | 个性化推荐 | 基于浏览历史+收藏+购买记录推荐 |
| 可复用现有接口                  | 冷启动推荐 | 无历史时返回热门商品       |

**前端改动**：

- 首页增加「为你推荐」板块
- 商品详情页底部增加「猜你喜欢」

***

### 3.5 优惠券/促销系统

**现状**：没有任何优惠手段。

**用户体验影响**：

- 缺少促进用户下单的动力
- 无法做拉新/促活运营活动

**后端配合需求**：

| 接口                        | 方法         | 说明                                |
| ------------------------- | ---------- | --------------------------------- |
| `POST /coupon/create`     | 创建优惠券(管理员) | 面额、门槛、有效期、数量                      |
| `POST /coupon/claim`      | 领取优惠券      | 用户领取                              |
| `GET /coupon/userList`    | 我的优惠券      | 未使用/已使用/已过期                       |
| `POST /order/applyCoupon` | 使用优惠券      | 下单时使用                             |
| 新建 `CouponModel`          | 优惠券模板      | 面额、门槛、有效期、库存                      |
| 新建 `UserCouponModel`      | 用户持有的优惠券   | userId, couponId, usedAt, orderId |

**前端改动**：

- 下单页增加「使用优惠券」选项
- 用户主页增加「我的优惠券」
- 首页可做领券入口

***

### 3.6 商品问答系统

**现状**：买家无法在商品页面提问。

**用户体验影响**：

- 同样的问题多个买家重复问（如"这个手机有划痕吗？"）
- 缺少互动氛围

**后端配合需求**：

| 接口                           | 方法   | 说明                                                |
| ---------------------------- | ---- | ------------------------------------------------- |
| `POST /product/question`     | 提问   | userId, productId, content                        |
| `POST /product/answer`       | 回答   | questionId, userId(seller), content               |
| `GET /product/question/list` | 问题列表 | 按商品ID，分页                                          |
| 新建 `QuestionModel`           | 问答模型 | productId, userId, content, answers\[], createdAt |

**前端改动**：

- 商品详情增加「问答」Tab
- 提问弹窗
- 回答输入框

***

### 3.7 验证码/安全增强

**现状**：已有图形验证码，但是：

- 登录没有验证码（只限流）
- 没有忘记密码功能
- 没有邮箱/手机验证码

**用户体验影响**：

- 忘记密码无法找回（只能联系管理员）
- 账号安全等级低

**后端配合需求**：

| 接口                          | 方法      | 说明         |
| --------------------------- | ------- | ---------- |
| `POST /user/forgotPassword` | 忘记密码    | 通过手机号验证码重置 |
| `POST /user/sendSmsCode`    | 发送短信验证码 | 对接短信服务商    |
| 修改登录                        | 增加验证码验证 | 登录加上图形验证码  |

**前端改动**：

- 登录页增加「忘记密码」链接
- 重置密码流程页面

## 4. UI/UX 细节优化（低优先级）

### 4.1 图片查看器增强

**现状**：商品图片只能「拖拽查看」，体验有限。

**改进方案**：

- 点击图片弹出 Lightbox 画廊（左右切换、缩放、全屏）
- 后端无需改动，纯前端实现

### 4.2 骨架屏加载

**现状**：数据加载时显示「加载中」文字。

**改进方案**：

- 商品列表用卡片骨架屏占位
- 后端无需改动，纯前端实现

### 4.3 空状态引导

**现状**：空数据时只显示「暂无数据」。

**改进方案**：

- 空状态配插画 + 引导操作（如"去发布第一个商品"）
- 后端无需改动，纯前端实现

### 4.4 操作确认与撤销

**现状**：删除商品、取消订单等操作没有二次确认。

**改进方案**：

- 所有敏感操作弹窗确认
- 部分操作支持短时间内撤销（如取消订单后 5 分钟内可恢复）
- 后端需增加 `POST /order/restore` 接口

### 4.5 页面过渡动画

**现状**：页面切换较生硬。

**改进方案**：

- Vue Router 增加过渡动画（fade/slide）
- 后端无需改动，纯前端实现

### 4.6 数据导出

**现状**：用户无法导出自己的订单/商品数据。

**改进方案**：

| 接口                    | 方法   | 说明              |
| --------------------- | ---- | --------------- |
| `GET /order/export`   | 导出订单 | 返回 CSV/Excel 文件 |
| `GET /product/export` | 导出商品 | 返回 CSV/Excel 文件 |

### 4.7 批量操作

**现状**：商品管理只能逐个操作。·

**改进方案**：

- 商品列表增加多选 → 批量上架/下架/删除
- 后端需增加 `POST /product/batchUpdate` 接口

## 5. 后端架构改进建议

### 5.1 WebSocket 实时推送

**现状**：通知系统靠前端轮询（30秒查未读数、60秒刷新列表），延迟高且浪费资源。

**改进方案**：

- 引入 Socket.io
- 事件：新订单通知、支付成功、新消息、系统通知
- 前端连接后自动加入用户房间，后端事件触发时实时推送

### 5.2 全文搜索引擎

**现状**：商品搜索使用 MongoDB 的正则匹配，性能差且不支持分词。

**改进方案**：

- 引入 Elasticsearch 或 MongoDB Atlas Search
- 实现中文分词搜索、拼音搜索、纠错建议

### 5.3 图片 CDN 加速

**现状**：图片存储在后端服务器本地 `/uploads` 目录。

**改进方案**：

- 接入阿里云 OSS / 七牛云
- 后端上传时直接传到 CDN，返回 URL
- 图片处理（缩略图、水印）由 CDN 完成

### 5.4 数据统计与分析

**现状**：仪表盘数据较基础。

**改进方案**：

| 接口                                 | 方法   | 说明                    |
| ---------------------------------- | ---- | --------------------- |
| `GET /admin/analytics/overview`    | 综合数据 | 今日/本周/本月 GMV、订单数、新增用户 |
| `GET /admin/analytics/salesTrend`  | 销售趋势 | 按天/周/月返回销售额曲线         |
| `GET /admin/analytics/productRank` | 商品排行 | 销量 TOP 商品             |
| `GET /admin/analytics/userGrowth`  | 用户增长 | 新增用户趋势                |

### 5.5 接口缓存优化

**现状**：热门商品、标签列表等高频率读接口每次都查数据库。

**改进方案**：

- 引入 Redis 缓存
- 缓存热门商品列表（TTL 5分钟）
- 缓存标签列表（TTL 1小时）
- 缓存验证码（替代内存 Store）
